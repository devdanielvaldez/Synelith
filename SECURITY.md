# Security Policy and Biocybersecurity Framework

## 1. Scope & Commitment

NeuroGenesis AI processes complex biomedical data, interacts with external academic APIs, parses untrusted publications, and executes computational pipelines. We prioritize system isolation, data provenance, and defense-in-depth across our software architecture.

This security policy defines our vulnerability reporting procedures, threat model, and biocaptive isolation standards.

---

## 2. Supported Versions

Only the latest release branch and the active `main` branch receive active security patches.

| Version | Supported | Notes |
|---|---|---|
| `0.1.x` (Sprint 1 / Active Dev) | Yes | Current development target |
| `< 0.1.0` | No | Experimental pre-release |

---

## 3. Reporting a Vulnerability

**DO NOT report security vulnerabilities through public GitHub issues or discussions.**

If you discover a security vulnerability, prompt injection vector, sandbox bypass, or data leakage flaw, please report it confidentially:

* **Email:** [security@neurogenesis.ai](mailto:security@neurogenesis.ai)
* **Response SLA:** Within **48 hours**, our security team will acknowledge receipt and provide an initial triage assessment.
* **Coordination Window:** We ask for a standard 90-day coordinated disclosure window before public disclosure.

### What to Include in Your Report
1. Detailed description of the vulnerability and attack vector.
2. Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
3. Affected components, endpoints, or agent modules.
4. Potential impact (e.g., container breakout, unauthorized API egress, arbitrary code execution, indirect prompt injection).
5. Proposed remediations or mitigations (if known).

---

## 4. Threat Model & Specific Vectors

### 4.1 Indirect Prompt Injection via Literature
Scientific publications, abstracts, preprints, and user-provided PDFs are treated as **untrusted, hostile inputs**.
- Ingestion pipelines must sanitize literature text prior to feeding it into LLM contexts.
- Structural XML/HTML delimiters and explicit instruction-content separation must be enforced.
- Extraction prompts must never have access to execution tools or external egress channels.

### 4.2 Computational Sandbox Isolation
Any user- or agent-generated code execution must occur within strictly isolated, unprivileged environments:
- Ephemeral containers with read-only root filesystems.
- Network access disabled by default (`--network none`).
- Strict resource caps: CPU quotas, memory limits, and process execution timeouts.
- No mounting of host filesystems, Docker sockets, or sensitive environment variables.

### 4.3 Data Privacy & Dual-Use Biosecurity
- **Protected Health Information (PHI) & Clinical Data:** The platform must not ingest identifiable patient health information without signed Data Use Agreements (DUAs) and IRB oversight.
- **Biosecurity & Dual-Use Research of Concern (DURC):** Automated pipelines must not generate synthesis instructions, acquisition vectors, or optimization paths for dangerous toxins or select biological agents.

---

## 5. Medical & Clinical Disclaimer

**NeuroGenesis AI is a computational research and hypothesis generation platform.**

* The software is **NOT** a medical device, diagnostic system, or clinical decision support tool.
* Inferences, associations, and hypotheses generated by the system **must not** be used to prescribe medication, select clinical trials for individuals, diagnose patients, or modify treatments.
* The maintainers and contributors assume no liability for experimental or clinical decisions taken based on outputs produced by this software.
